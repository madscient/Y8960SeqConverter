# 変換の中身

`y8conv` が元データの何を Y8960 のシーケンスデータの何に写すか。写らないものと、
元のドライバと鳴り方が違うところも書く。元のドライバの動作は、そのプログラムを
読んで確かめてある。

Y8960 側の用語（イベント、走行状態、音色集合）は Y8960 BASIC Extension の
`doc/bytecode.md` のもの。

## 時間

| 元 | Y8960 |
|---|---|
| 音長 1（1/60 秒） | 1 tick |
| ―― | テンポ 75（最初のトラックの頭に置く） |

テンポ 75 で 1 tick がちょうど 1/60 秒になる。丸めは入らない。

- 元データが 50Hz の機械で作られていた場合は、1.2 倍速く鳴る
- 1 つのイベントが持てる音長は 8191 tick まで。それより長い音符はタイで、休符と
  待ちは同じイベントを重ねてつなぐ

## チャンネル

| 元 | Y8960 |
|---|---|
| FM メロディ 1-9 | OPLLEX1 の CH0-8 |
| FM リズム | OPLLEX1 の CH10 |
| MuSICA の PSG（10-12） | SSGS の CH0-2 |
| MuSICA の SCC（13-17） | SCC の CH0-4 |

- 中身が何も無いチャンネルはトラックにしない
- OPLLDRV のヘッダでオフセットが 0 のチャンネルは、使わないチャンネルとして
  読み飛ばす
- シーケンスは 16 トラックまで。越えるときは変換しない（`--drop` で外す）

## 繰り返し

元のドライバは、曲の終わりまで来たら頭から演奏し直す（回数は演奏を始める側が
決める）。Y8960 のシーケンスも同じで、各トラックの終わりの `FF` がそれにあたる。

MuSICA のシーケンスは「ブロックを何回」の並び。

- 2 回以上のものはループ（`42` … `E2`）にする
- 同じブロックの並びが続けて繰り返されるところ（A B A B A B）も、ループにまとめる
- **ループにするのは、ループの本体が周ごとに同じバイト列になるときだけ。**
  1 周目だけ音量や音色の設定が要る、といった場合は 1 周目を書き出して、残りを
  ループにする。それでもそろわない場合は全部書き出す
- ループの入れ子は 4 段まで（読み手の上限）。それより深いものは書き出す

## FM メロディ

| 元 | Y8960 | 備考 |
|---|---|---|
| `01h`-`5Fh` 音符 | 音符 | **元と同じ周波数で鳴る番号に写す。** FM は元の O*n* が Y8960 の O(*n*−1) になる（下記「音の高さ」） |
| `00h` 休符 | `0C` 休符 | OPLLDRV でレガートの音符のあとの休符は `0E` 待つだけ（下記） |
| `60h`-`6Fh` 音量 | `81` 音量 | 元の減衰量 *a* を、レベル 15−*a* として |
| `70h` 音色 0 | `85` | その時点のユーザー音色（下記） |
| `71h`-`7Fh` 音色 1-15 | `82` 1-15 | OPLLEX のバンク 0（YM2413 の内蔵音色） |
| `80h` `81h` サステイン | `E0` レジスタ書き込み | 20h＋CH の bit5 だけを書き換える。OPLLDRV は `80h` で設定・`81h` で解除、MuSICA は `81h` で設定・`80h` で解除（どちらも元のドライバの動作。OPLLDRV は仕様書の記述と逆） |
| `82h` 拡張音色（OPLLDRV） | `85` | 既定は Y8960 のプリセット `@n` の音色。`--rom-voices` を渡すとその音色。どちらも移調は掛けない（元のドライバと同じ）。番号は 0-63 で、64 以上は警告して下位 6 ビットを使う |
| `83h` ユーザー音色 | `85` | 8 バイトの音色を Y8960 の音色（12 バイト）に直して音色集合に入れる |
| `84h` `85h` レガート | `45` タイ／レガート | **レガートの間に読んだ音符は、次の音符へつながる。** 次の音符の前に `45` を置く。レガートの間の音符は Q を 8 にする（下記） |
| `86h` Q 1-8 | `83` Q | |
| `86h` Q 0（MuSICA） | 音符＋`0C` 休符 1 | 「最後の 1 カウントを切る」を書き出す |
| `86h` Q 0、Q 9 以上（OPLLDRV） | `83` Q | 元のドライバと同じく Q の下位 3 ビットを使い、0 は 8 とする |
| `8Ch` レジスタ書き込み（MuSICA） | `E0` | OPLLEX が受け付けないレジスタは落とす（警告） |
| `8Dh` ウェイト（MuSICA） | `0E` 待つだけ | |

- **つながるかどうかは、前の音符を読んだときのレガートで決まる。** 元のドライバは
  前の音符が終わる時点で切るかどうかを決め、そのとき後ろの `84h` はまだ読んで
  いないため。`85h a 84h b` の a と b はつながり、`a 85h b` の a と b は
  つながらない。MuSICA の MML の `(abc)d` は、a b c d がつながる。2 つのドライバで
  同じ
- **休符のあとは、MuSICA ではつながらない。OPLLDRV では、レガートの音符のあとの
  休符はキーに触れず、音はその休符のあいだも鳴り続けて、次の音符へつながる。**
  変換器はこの休符を `0E` 待つだけにし、次の音符の前に `45` を置く。MuSICA の
  Q 0 で切った音符のあとはつながらない
- **`83h` と OPLLDRV の `82h` は、ユーザー音色の中身を設定するだけ。** 鳴るのは
  `70h` で音色 0 を選んだとき（どちらのドライバも同じ）。MuSICA の `82h` は
  1 バイトを読み捨てるだけ
- **`83h` と OPLLDRV の `82h` は、音色 0 を使っている他のチャンネルの音も変える**（チップの
  ユーザー音色は 1 つ）。Y8960 では、その音色を選んだチャンネルで初めて読み込まれる
  ので、音色 0 を選んでいないチャンネルで `82h` `83h` を書いたときの他のチャンネル
  への影響は写らない
- 最初の音符より前に音量と音色が無いときは、元のドライバの初期値を書く。
  MuSICA は仕様書のとおり音量 `60h`、音色 `7Ah`。OPLLDRV は演奏を始めるときに
  音量と音色を設定し直さず、チップに残っている値で鳴る。変換器は、FM-BIOS が
  起動時に設定する値（音量は減衰量 3、音色 11）を書く
- MuSICA の元のドライバは、演奏を始めるときにチップの音量と音色を 0 にし、`60h`
  `7Ah` を最初の音量か音色の指定を読んだときにチップへ送る。それより前の音符は
  ユーザー音色・最大の音量で鳴るが、変換器は `60h` `7Ah` で鳴らす
- Q が 1-7 の音符が鳴る長さは、音長 × Q ÷ 8 の切り捨て（0 なら 1）。2 つの
  ドライバと Y8960 の読み手は同じ計算をする

## 音の高さ

**元と同じ周波数で鳴るように写す。** 楽譜上のオクターブの数字は変わることがある。

| 元 | 元の O4A | Y8960 |
|---|---|---|
| MuSICA の FM | 約 218Hz（ブロック 3） | 1 オクターブ下の番号（元の O4A が Y8960 の O3A） |
| MuSICA の PSG・SCC | 440Hz | 同じ番号 |
| OPLLDRV の FM | 約 218Hz（ブロック 3） | MuSICA の FM と同じ |

Y8960 の O4A はどの音源でも 440Hz。

- 元の FM の O1 は Y8960 の O0 になる。Y8960 の FM は O0 の C-F# をブロック 0 の
  まま F-Number を下げて鳴らすので、音程の精度が少し落ちる（Y8960 BASIC Extension の
  `basic-reference.md`「出せない高さ」）

## FM リズム

| 元 | Y8960 |
|---|---|
| 発声（`001BSTCH`＋音長） | `C8` 楽器と音長 |
| 楽器の無い発声 | `0E` 待つだけ |
| `C1h` ウェイト（MuSICA） | `0E` 待つだけ |
| 音量（`101BSTCH`＋音量） | `D8`（楽器ごとの通常音量）、`A9`（5 つとも同じとき） |
| `C0h` レジスタ書き込み（MuSICA） | `E0` |

**元の楽器ごとの音量を、Y8960 の楽器ごとの通常音量にそのまま写す。** アクセントは
使わない（`A8 00`）。

- 音量は、その楽器を叩くときに書く。叩かない楽器の音量を変えるのは、同じ値にする
  楽器を叩くときに相乗りできる場合だけ。鳴り残っている楽器の音量が、元より遅れて
  変わることがある
- トラックで最初に叩くときは、読み手の既定値（8）と同じ音量でも書く。Y8960 は
  シーケンスを繰り返したとき楽器の音量を戻さないため
- `D8` に対応していない読み手は `D8` を読み飛ばすので、`D8` で決めた音量は効かない
- 楽器を指定しない音量（`101 00000`）は何もしない（元のドライバと同じ）
- 音量の初期値は、OPLLDRV は減衰量 3、MuSICA は減衰量 0（どちらも元のドライバが
  演奏を始めるときに設定する値）
- **Y8960 の読み手は、叩くたびに 5 つの楽器をすべて止めてから鳴らす。** MuSICA の
  元のドライバも同じ。OPLLDRV の元のドライバは叩く楽器だけを止めるので、OPLLDRV の
  曲では、叩かない楽器の鳴り残り（シンバルやハイハットの余韻）が、変換後は次の
  打撃で切れる
- **MuSICA の楽器の無い発声は、鳴り残っている楽器をすべて止める。** 変換後の
  `0E` は止めないので、その余韻は切れずに続く

## MuSICA の PSG と SCC

| 元 | Y8960 | 備考 |
|---|---|---|
| 音符・休符・ウェイト | 音符・`0C` 休符・`0E` 待つだけ | |
| `60h`-`6Fh` 音量 | `81` 音量 | 元のレベル 0-15 をそのまま |
| `83h` 音色（PSG） | `B2`（エンベロープ）、`E0` でレジスタ 06h（ノイズ周波数）、`82`（トーンとノイズの切り替え） | |
| `83h` 音色（SCC） | `B2`（エンベロープ）、`85`（波形。音色集合に入れる） | |
| `84h` `85h` レガート | `45` タイ／レガート | FM と同じ |
| `86h` Q | `83` Q、Q 0 は音符＋`0C` 休符 1 | FM と同じ |
| `8Ch` レジスタ書き込み | `E0` | PSG で 0Eh 以上は落とす（警告）。SCC は番号に 80h を足す（元のドライバが 9880h＋番号に書くため） |

- **音色が持つソフトウェアエンベロープ（先頭の 4 バイト）は、Y8960 のソフトウェア
  エンベロープに写す。** 同じ中身のエンベロープは 1 つにまとめて 1 から番号を振り、
  シーケンスに入れる（チャンク `04`）。1 曲 31 個まで。越えると変換しない
- 元のアタック・ディケイ・リリースの 1 バイト（上位 4 ビットが割り込みの数、下位
  4 ビットが変化量）は、そのまま書く。Y8960 も同じ形で持つ
- ただし上位か下位が 0 のバイトは、Y8960 には無い。元のドライバでは、上位の 0 は
  256 回の割り込みに 1 回、下位の 0 は動かないことを表す。これは速さ（変化量 ÷
  割り込みの数）が最も近い `F1`（15 回に 1 ずつ）に寄せる（警告）
- 音色（`83h`）が無い PSG と SCC は、エンベロープ無し（`B2 0`、トラックの初期値）
  で鳴る。元のドライバのこのときのエンベロープは、キーオンで最大、キーオフで 0 に
  1 コマで動くもので、エンベロープ無しと同じに鳴る
- SCC で波形が決まる前に音符があるときは、Y8960 のプリセット波形 0 で鳴らす（警告）
- **SCC の音量は、Y8960 の表を通さずに書く**（トラックの頭に `B3 0`）。元の
  ドライバは 0-15 の値をそのまま SCC の音量レジスタに書くので、それに合わせた。
  ソフトウェアエンベロープの値も同じく表を通らない
- 音量の初期値は仕様書のとおり `60h`（PSG と SCC では最小）
- ノイズ周波数は、音色がノイズを鳴らすときだけ書く（元のドライバと同じ）
- `82h` は 1 バイトを読み捨て、`8Ah` は何もしない（元のドライバと同じ）

## 変換しないもの

| 元 | |
|---|---|
| MuSICA `87h` デチューン | 警告を出して落とす |
| MuSICA `88h` ポルタメント | 同上 |
| MuSICA `89h` ビブラート | 同上 |
| MuSICA `8Bh` LFO 速度 | 同上 |
| MuSICA の PSG への `8Ch` のうち、0Eh 以上 | 同上 |

Y8960 のバイトコードには LFO が無い。ビブラートとポルタメントを音程の変化の
イベントに書き出すと、1 トラック 2048 バイトにはまず収まらない。

元のドライバも `8Ch` をチャンネルの音源に書くので、PSG への 0Eh 以上の
書き込みは、元の機械でも音に届かない。落としても鳴り方は変わらない。

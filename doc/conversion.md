# 変換の中身

`y8conv` が元データの何を Y8960 のシーケンスデータの何に写すか。写らないものと、
元のドライバの動作を確かめずに決めているところも書く。

Y8960 側の用語（イベント、走行状態、音色集合）は Y8960 BASIC Extension の
`doc/bytecode.md` のもの。

「確かめていない」と書いた項目は、元のドライバのプログラムを読んで確かめたもの
ではなく、仕様書が黙っているところを通例に従って決めたもの。元の機械で聞いた音と
違う場合は、まずここを疑う。

## 時間

| 元 | Y8960 |
|---|---|
| 音長 1（1/60 秒） | 1 tick |
| ―― | テンポ 75（最初のトラックの頭に置く） |

テンポ 75 で 1 tick がちょうど 1/60 秒になる。丸めは入らない。

- 元データが 50Hz の機械で作られていた場合は、1.2 倍速く鳴る
- 1 つのイベントが持てる音長は 8191 tick まで。それより長い音符はタイで、休符と
  待ちは同じイベントを重ねてつなぐ

## チャンネル

| 元 | Y8960 |
|---|---|
| FM メロディ 1-9 | OPLLEX1 の CH0-8 |
| FM リズム | OPLLEX1 の CH10 |
| MuSICA の PSG（10-12） | SSGS の CH0-2 |
| MuSICA の SCC（13-17） | SCC の CH0-4 |

- 中身が何も無いチャンネルはトラックにしない
- シーケンスは 16 トラックまで。越えるときは変換しない（`--drop` で外す）

## 繰り返し

元のドライバは、曲の終わりまで来たら頭から演奏し直す（回数は演奏を始める側が
決める）。Y8960 のシーケンスも同じで、各トラックの終わりの `FF` がそれにあたる。

MuSICA のシーケンスは「ブロックを何回」の並び。

- 2 回以上のものはループ（`42` … `E2`）にする
- 同じブロックの並びが続けて繰り返されるところ（A B A B A B）も、ループにまとめる
- **ループにするのは、ループの本体が周ごとに同じバイト列になるときだけ。**
  1 周目だけ音量や音色の設定が要る、といった場合は 1 周目を書き出して、残りを
  ループにする。それでもそろわない場合は全部書き出す
- ループの入れ子は 4 段まで（読み手の上限）。それより深いものは書き出す

## FM メロディ

| 元 | Y8960 | 備考 |
|---|---|---|
| `01h`-`5Fh` 音符 | 音符 | **元と同じ周波数で鳴る番号に写す。** FM は元の O*n* が Y8960 の O(*n*−1) になる（下記「音の高さ」） |
| `00h` 休符 | `0C` 休符 | |
| `60h`-`6Fh` 音量 | `81` 音量 | 元の減衰量 *a* を、レベル 15−*a* として |
| `70h` 音色 0 | `85` | その時点のユーザー音色（下記） |
| `71h`-`7Fh` 音色 1-15 | `82` 65-79 | OPLLEX のバンク 0（YM2413 の内蔵音色） |
| `80h` `81h` サステイン | `E0` レジスタ書き込み | 20h＋CH の bit5 だけを書き換える |
| `82h` 拡張音色（OPLLDRV） | `85` | 既定は Y8960 のプリセット `@n` の音色。`--rom-voices` を渡すとその音色 |
| `83h` ユーザー音色 | `85` | 8 バイトの音色を Y8960 の 32 バイトの音色に直して音色集合に入れる |
| `84h` `85h` レガート | `45` タイ／レガート | レガートの間は、休符の直後でない音符の前に `45` を置き、Q を 8 にする |
| `86h` Q 1-8 | `83` Q | |
| `86h` Q 0（MuSICA） | 音符＋`0C` 休符 1 | 「最後の 1 カウントを切る」を書き出す |
| `8Ch` レジスタ書き込み（MuSICA） | `E0` | OPLLEX が受け付けないレジスタは落とす（警告） |
| `8Dh` ウェイト（MuSICA） | `0E` 待つだけ | |

- **ユーザー音色の選び方は、2 つのドライバで違う。** MuSICA の `83h` は音色データを
  設定するだけで、`70h` で選んだときに鳴る（仕様書どおり）。OPLLDRV の `83h` は
  その場でその音色を選ぶ（**確かめていない**。uniskie 氏の OPLDRV_tool の読み方に
  合わせた）
- **MuSICA の `83h` は、音色 0 を使っている他のチャンネルの音も変える**（チップの
  ユーザー音色は 1 つ）。Y8960 では、その音色を選んだチャンネルで初めて読み込まれる
  ので、音色 0 を選んでいないチャンネルで `83h` を書いたときの他のチャンネルへの
  影響は写らない
- 最初の音符より前に音量と音色が無いときは、元のドライバの初期値を書く。
  MuSICA は仕様書のとおり音量 `60h`、音色 `7Ah`。OPLLDRV は仕様書に無いので、
  音量は減衰量 3、音色は `7Ah` にしている（**確かめていない**）
- Q が 1-7 の音符が鳴る長さは、音長 × Q ÷ 8 の切り捨て（0 なら 1）。MuSICA の
  ドライバと Y8960 の読み手は同じ計算をする。OPLLDRV も同じと見ている
  （**OPLLDRV は確かめていない**）

## 音の高さ

**元と同じ周波数で鳴るように写す。** 楽譜上のオクターブの数字は変わることがある。

| 元 | 元の O4A | Y8960 |
|---|---|---|
| MuSICA の FM | 約 218Hz（ブロック 3） | 1 オクターブ下の番号（元の O4A が Y8960 の O3A） |
| MuSICA の PSG・SCC | 440Hz | 同じ番号 |
| OPLLDRV の FM | ―― | MuSICA の FM と同じ扱い（**確かめていない**） |

Y8960 の O4A はどの音源でも 440Hz。

- 元の FM の O1 は Y8960 の O0 になる。Y8960 の FM は O0 の C-F# をブロック 0 の
  まま F-Number を下げて鳴らすので、音程の精度が少し落ちる（Y8960 BASIC Extension の
  `basic-reference.md`「出せない高さ」）

## FM リズム

| 元 | Y8960 |
|---|---|
| 発声（`001BSTCH`＋音長） | `C8` 楽器と音長 |
| 楽器の無い発声 | `0E` 待つだけ |
| 音量（`101BSTCH`＋音量） | `A9` `AA` `A8` |
| `C0h` レジスタ書き込み（MuSICA） | `E0` |

**元は楽器ごとに音量を持つが、Y8960 のリズムは「普通の音量」と「アクセントの
音量」の 2 つしか持たない。** 打撃ごとに、叩く楽器の音量を 2 つに振り分けて
書き出す。

- 同時に叩く楽器の音量が 3 種類以上あるときは、真ん中のものを近いほうに寄せる（警告）
- Y8960 では、打撃のたびに叩かない楽器にも普通の音量が設定される。鳴り残っている
  楽器の音量が変わることがある
- 楽器を指定しない音量（`101 00000`）は、全部の楽器の音量とする（**確かめていない**。
  uniskie 氏の OPLDRV_tool の読み方）
- 音量の初期値は、MuSICA は減衰量 0、OPLLDRV は減衰量 3 にしている
  （**確かめていない**。どちらの仕様書にも無い）

## MuSICA の PSG と SCC

| 元 | Y8960 | 備考 |
|---|---|---|
| 音符・休符・ウェイト | 音符・`0C` 休符・`0E` 待つだけ | |
| `60h`-`6Fh` 音量 | `81` 音量 | 元のレベル 0-15 をそのまま |
| `83h` 音色（PSG） | `B2`（エンベロープ）、`E0` でレジスタ 06h（ノイズ周波数）、`82`（トーンとノイズの切り替え） | |
| `83h` 音色（SCC） | `B2`（エンベロープ）、`85`（波形。音色集合に入れる） | |
| `84h` `85h` レガート | `45` タイ／レガート | FM と同じ |
| `86h` Q | `83` Q、Q 0 は音符＋`0C` 休符 1 | FM と同じ |
| `8Ch` レジスタ書き込み | `E0` | PSG で 0Eh 以上は落とす（警告）。SCC は番号に 80h を足す（元のドライバが 9880h＋番号に書くため） |

- **音色が持つソフトウェアエンベロープ（先頭の 4 バイト）は、Y8960 のソフトウェア
  エンベロープに写す。** 同じ中身のエンベロープは 1 つにまとめて 1 から番号を振り、
  シーケンスに入れる（チャンク `04`）。1 曲 31 個まで。越えると変換しない
- 元のアタック・ディケイ・リリースの 1 バイト（上位 4 ビットが割り込みの数、下位
  4 ビットが変化量）は、Y8960 の 0-32 のうち同じ組のものに写す。MuSICA の音色は
  この組でできている（サンプル 85 本の 5934 個がすべて一致した）。一致しない
  バイトは、速さ（変化量 ÷ 割り込みの数）が最も近いものに寄せる（警告）
- 音色（`83h`）が無い PSG と SCC は、エンベロープ無し（`B2 0`、トラックの初期値）
  で鳴る。元のドライバのこのときの初期値は**確かめていない**
- SCC で波形が決まる前に音符があるときは、Y8960 のプリセット波形 0 で鳴らす（警告）
- 音量の初期値は仕様書のとおり `60h`（PSG と SCC では最小）
- ノイズ周波数は、音色がノイズを鳴らすときだけ書く（元のドライバと同じ）
- `82h` は 1 バイトを読み捨て、`8Ah` は何もしない（元のドライバと同じ）

## 変換しないもの

| 元 | |
|---|---|
| MuSICA `87h` デチューン | 警告を出して落とす |
| MuSICA `88h` ポルタメント | 同上 |
| MuSICA `89h` ビブラート | 同上 |
| MuSICA `8Bh` LFO 速度 | 同上 |
| MuSICA の PSG への `8Ch` のうち、0Eh 以上 | 同上 |

Y8960 のバイトコードには LFO が無い。ビブラートとポルタメントを音程の変化の
イベントに書き出すと、1 トラック 2048 バイトにはまず収まらない。

元のドライバも `8Ch` をチャンネルの音源に書くので、PSG への 0Eh 以上の
書き込みは、元の機械でも音に届かない。落としても鳴り方は変わらない。

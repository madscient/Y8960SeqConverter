# MuSICA ドライバの動作（BGM.BIN を読んで確かめたこと）

**この文書は情報リソース。** MuSICA のドライバ `BGM.BIN` を逆アセンブルして、
仕様書（uniskie 氏による非公式版 `MuSICA_Driver_Data_Manual.md`）が書いていない
動作と、仕様書と食い違う動作を書き留めたもの。読者は、このリポジトリで変換を
書く人と、Y8960 BASIC Extension 側で MuSICA 互換のエンベロープを実装する人。

- 読んだもの: uniskie/msx_music_data の `Mus-*/BGM.BIN`（3 つとも同一のファイル）。
  BSAVE の見出しで CE00h-DDE0h に置かれる
- ここに書いたことは、すべてコードを読んで確かめたもの。**実機やエミュレータで
  走らせてはいない**
- 番地は、確かめ直すときの手がかりとして添える。ドライバのコードそのものは
  載せない

## チャンネルの番号と作業域

ドライバはチャンネルを 0 起点の番号（CE9Fh）で持つ。0-8 が FM、9-11 が PSG、
12-16 が SCC。多くの処理がこの番号で「9 未満」「12 未満」と分岐する。

PSG と SCC のチャンネルは、エンベロープのための 9 バイトの作業域を持つ
（PSG は DD94h から、SCC は DDAFh から、チャンネルごとに 9 バイト）。

| オフセット | 内容 |
|---|---|
| +0 | アタック（音色の +0） |
| +1 | ディケイ（音色の +1） |
| +2 | サスティンレベル（音色の +2） |
| +3 | リリース（音色の +3） |
| +4 | ノイズ周波数（PSG の音色の +4） |
| +5 | トーンとノイズのオン・オフ（PSG の音色の +5） |
| +6 | 段階: 0 アタック、1 ディケイ、2 サスティン、3 リリース、4 停止 |
| +7 | カウンタ |
| +8 | エンベロープの値（0-15） |

## コマンドの大きさ

振り分け表は D6D1h。80h-8Dh の 14 個。

| コマンド | 後ろに続くバイト | 仕様書との違い |
|---|---|---|
| `82h` | 1（読み捨てる） | 仕様書は「サポートしていない」とだけ書く |
| `8Ah` | 0（何もしない） | 同上 |
| `87h` `88h` `89h` `8Bh` | 1 | |
| `8Ch` | 2 | |
| `8Dh` | 音長 | |

## レジスタ書き込み（`8Ch`）

**チャンネルの音源に書く。** 仕様書どおり（DAFFh）。

| チャンネル | 書き先 |
|---|---|
| FM | FM-BIOS の WRTOPL（4110h）。OPLL のレジスタ番号そのまま |
| PSG | MSX BIOS の WRTPSG（0093h）。番号そのまま。0Eh と 0Fh は I/O ポートで、音のレジスタは 0Dh まで。16 以上の番号は AY-3-8910 のアドレスの上位 4 ビットが合わず選ばれない（**推測** ―― AY-3-8910 の一般的な仕様による。実機では試していない） |
| SCC | **9880h ＋ 番号**。レジスタの窓の先頭（9800h）から数えると、番号に 80h を足した位置 |

## 音色（`83h`）

DA35h。

| チャンネル | 動作 |
|---|---|
| FM | 8 バイトを OPLL のレジスタ 00h-07h に**その場で**書く。どの音色を選んでいるかに関係なく書く |
| PSG | 6 バイトを作業域に写し、ミキサー（レジスタ 7）を書き直す。**ノイズがオン（+5 の bit3 が 0）のときだけ**、ノイズ周波数をレジスタ 6 に書く |
| SCC | 4 バイト（エンベロープ）を作業域に写し、32 バイトの波形をチャンネルの波形メモリに書く。チャンネル 4（0 起点）は 3 と同じ場所に書く |

## 音長とゲート（Q）

音符を読むと、ドライバは音長 L から「残り」と「キーオフする時点」を決める（D4AEh）。

| 場合 | 音が鳴る長さ |
|---|---|
| レガート中、または `8Dh`（ウェイト） | 切らない |
| Q 8 | 切らない（次の音符の直前、同じ割り込みで切る） |
| Q 0 | L − 1 |
| Q 1-7 | L × Q ÷ 8 の切り捨て。0 なら 1 |

**Q 1-7 と Q 8 は、Y8960 の読み手の計算とまったく同じ。**

**キーオフするかどうかは、その音符が終わる割り込みで、後ろのコマンドを読む前に
決まる。** そのときレガートなら切らない（D67Fh が作業域 +0Ch の bit5-6 を見る）。
レガートは音符を読んでから終わるまで変わらないので、**「その音符を読んだときに
レガートだったか」で決まる**。後ろの `84h`（レガート OFF）は間に合わない。

- 次の音符は、キーが押されたままなら鳴らし直さない（FM はキーオンを書かず、PSG と
  SCC はエンベロープをやり直さない）。だから `85h a 84h b` では a と b がつながる
- 逆に `a 85h b` の a はつながらない（a が終わるときはまだレガートでない）
- MuSICA の MML の `( … )` は、`(` が `85h`、`)` が `84h` になる。`(abc)d` では、
  c を読んだときにレガートなので **c と d もつながる**。`(d i50) d i` は、d を
  2 つに分けて後半にだけビブラートを掛けるタイとして使われている（uniskie 氏の
  msx_music_data の MML と .BGM を並べて確かめた）

- 音長 0 の音符は、残りが 0 から 1 を引いた FFFFh になる。仕様書が「0 の動作は
  保証しない」と書いているもの
- 1 回の割り込みで、まず「残りがキーオフする時点に等しいか」を見てキーオフし、
  次に残りが 0 ならコマンドを読み、0 でなければ残りを 1 減らす（D669h）

## PSG と SCC のキーオンとキーオフ

D92Dh。

- **音符は、キーが離れているときだけエンベロープを始めからやり直す。** キーが
  押されたまま（レガート中、Q で切っていない）の音符は、音程だけを変え、
  エンベロープはそのまま続く
- 休符はキーを離し、エンベロープをリリースに入れる。音は止めない。リリースが
  0 に着くまで鳴り続ける
- Q で切る時点でも、同じくリリースに入る

## エンベロープ

D742h（1 回の割り込みぶん）、D7BEh（キーオン）、D7E9h（キーオフ）。

各バイトの上位 4 ビットがカウンタ、下位 4 ビットが変化量。

**キーオン:** 段階をアタック、値を 0、カウンタをアタックのカウンタにする。

**キーオフ:** 段階をリリース、カウンタをリリースのカウンタにする。値はそのまま
（アタックやディケイの途中でも、その値からリリースする）。

**割り込みごと**（そのチャンネルのコマンドを読み終えたあと。キーオンした割り込み
でも走る）:

| 段階 | 動作 |
|---|---|
| アタック | カウンタを 1 減らす。0 になったら、カウンタを入れ直し、値に変化量を足す。15 以上になったら値を 15 にしてディケイへ（カウンタはディケイのもの） |
| ディケイ | カウンタを 1 減らす。0 になったら、カウンタを入れ直し、値から変化量を引く。負になるか、サスティンレベルを下回ったら、値をサスティンレベルにしてサスティンへ |
| サスティン | 何もしない |
| リリース | カウンタを 1 減らす。0 になったら、カウンタを入れ直し、値から変化量を引く。負になったら値を 0 にして停止へ |
| 停止 | 何もしない（出力だけ書き直す） |

ここから導かれること:

- カウンタが 1 のアタックは、キーオンした割り込みで最初の 1 歩を進む。カウンタ n
  なら、キーオンを含めて n 回目の割り込みで進む
- **カウンタ 0 は 256 回にあたる**（0 から 1 減らすと 255 になり、0 にならない）。
  仕様書は範囲を 1-15 としている
- **アタックの変化量 0 は 15 に着かない**ので、値は 0 のまま動かない
- ディケイで値がちょうどサスティンレベルになったときは、ディケイのまま次の歩で
  下回ってからサスティンに入る。値はサスティンレベルのまま変わらない
- リリースで値がちょうど 0 になったときも、次の歩で停止に入る

**出力**（D423h）:

```
出力 = エンベロープの値 − (15 − max(0, チャンネル音量 − マスター音量))
       0 未満は 0
```

チャンネル音量は `60h`-`6Fh` の下位 4 ビット、マスター音量は BGMVOL で設定する
0-15（0 が最大、通常は 0）。PSG はレジスタ 8-10、SCC は 988Ah から始まる
音量レジスタに書く。

## 音の高さ

音符 `01h`-`5Fh` から n − 1 を 12 で割り、商をオクターブ、余りを半音にする
（D88Fh 以降）。

- **FM は商をそのままブロックにする。** O1 がブロック 0、O4 がブロック 3。
  F-Number の表（D913h）は C が 0ABh、A が 120h で、O4A は約 218Hz になる
- **PSG と SCC は同じ分周値の表（D9BEh）を使う。** 表は O1 の値（C が 0D5Dh、
  A が 7F2h）で、商のぶん右へシフトする。O4A は約 440Hz
- FM は PSG・SCC より 1 オクターブ低い

## まだ読んでいないもの

- `87h` デチューン、`88h` ポルタメント、`89h` ビブラート、`8Bh` LFO 速度の
  計算。値はそれぞれチャンネルの作業域（IX）の +12h、+19h、+15h、+13h と +14h に
  入り、音程の計算（D8BDh、D961h 付近）と毎割り込みの処理（D71Ch、D800h）が使う
- FM とリズムの初期値（音量、音色）
- リズムパートの処理
